# Settings for the Log4j Appender instrumentation

| System property                                                                    | Type    | Default | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------- | ------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `otel.instrumentation.common.logging.structured-attributes.included`               | String  |         | Comma-separated list of case-sensitive glob patterns for event-local structured log attribute keys to capture. Applies to Log4j `MapMessage` entries, SLF4J key-value pairs, Logback Logstash markers, and Logstash structured arguments. `*` matches any number of characters and `?` matches one character. Excluded patterns take precedence. An absent or empty included list captures every key not excluded. Under v3-preview, all structured attributes are captured by default. MDC and logger-context attributes remain separate and opt-in.                                                                                                                          |
| `otel.instrumentation.common.logging.structured-attributes.excluded`               | String  |         | Comma-separated list of case-sensitive glob patterns for event-local structured log attribute keys not to capture. Applies to Log4j `MapMessage` entries, SLF4J key-value pairs, Logback Logstash markers, and Logstash structured arguments. Excluded patterns take precedence over included patterns. An exclude-only selector captures every key not excluded; `*` captures no structured attributes. This does not affect `otel.event.name`, MDC, or logger context.                                                                                                                                                                                                       |
| `otel.instrumentation.log4j-appender.experimental-log-attributes`                  | Boolean | `false` | Enable the capture of experimental log attributes `thread.name` and `thread.id`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `otel.instrumentation.log4j-appender.experimental.capture-code-attributes`         | Boolean | `false` | Enable the capture of [source code attributes]. Note that capturing source code attributes at logging sites might add a performance overhead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `otel.instrumentation.log4j-appender.experimental.map-message-attributes.included` | String  |         | **Deprecated.** Use `otel.instrumentation.common.logging.structured-attributes.included` instead. This setting is ignored under v3-preview and will be removed in 3.0. Comma-separated list of case-sensitive glob patterns for `MapMessage` keys to capture as log attributes. `*` matches any number of characters and `?` matches one character, so `*` captures all `MapMessage` attributes. Excluded patterns take precedence over included patterns. No `MapMessage` attributes are captured unless an included pattern, an excluded pattern, or the deprecated `otel.instrumentation.log4j-appender.experimental.capture-map-message-attributes` setting is configured. |
| `otel.instrumentation.log4j-appender.experimental.map-message-attributes.excluded` | String  |         | **Deprecated.** Use `otel.instrumentation.common.logging.structured-attributes.excluded` instead. This setting is ignored under v3-preview and will be removed in 3.0. Comma-separated list of case-sensitive glob patterns for `MapMessage` keys not to capture as log attributes. `*` matches any number of characters and `?` matches one character. Excluded patterns take precedence over included patterns. An exclude-only selector captures all `MapMessage` attributes that do not match it.                                                                                                                                                                          |
| `otel.instrumentation.log4j-appender.experimental.capture-map-message-attributes`  | Boolean | `false` | **Deprecated.** Use `otel.instrumentation.common.logging.structured-attributes.included` instead. This setting is ignored under v3-preview and will be removed in 3.0. Outside v3-preview, `true` captures all `MapMessage` attributes and `false` captures none unless a source-specific included or excluded pattern is configured.                                                                                                                                                                                                                                                                                                                                          |
| `otel.instrumentation.log4j-appender.experimental.capture-marker-attribute`        | Boolean | `false` | Enable the capture of Log4j markers as attributes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `otel.instrumentation.log4j-appender.experimental.capture-template`                | Boolean | `false` | Enable the capture of the log message template (if arguments are provided).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `otel.instrumentation.log4j-appender.experimental.capture-arguments`               | Boolean | `false` | Enable the capture of the log message arguments.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `otel.instrumentation.log4j-appender.experimental.mdc-attributes.included`         | String  |         | Comma-separated list of case-sensitive glob patterns for context data keys to capture as log attributes. `*` matches any number of characters and `?` matches one character, so `*` captures all context data attributes. Excluded patterns take precedence over included patterns. No context data attributes are captured unless an included pattern, an excluded pattern, or the deprecated `otel.instrumentation.log4j-appender.experimental.capture-mdc-attributes` setting is configured; configuring only excluded patterns captures all context data attributes that do not match them.                                                                                |
| `otel.instrumentation.log4j-appender.experimental.mdc-attributes.excluded`         | String  |         | Comma-separated list of case-sensitive glob patterns for context data keys not to capture as log attributes. `*` matches any number of characters and `?` matches one character. Excluded patterns take precedence over included patterns. No context data attributes are captured unless an included pattern, an excluded pattern, or the deprecated `otel.instrumentation.log4j-appender.experimental.capture-mdc-attributes` setting is configured; configuring only excluded patterns captures all context data attributes that do not match them.                                                                                                                         |
| `otel.instrumentation.log4j-appender.experimental.capture-mdc-attributes`          | String  |         | Deprecated include-only alias for `otel.instrumentation.log4j-appender.experimental.mdc-attributes.included`. It does not support glob patterns: a list containing only `*` captures all context data attributes, and otherwise every entry, including one containing `*` or `?`, is matched as a literal context data key. It is ignored when an included or excluded pattern is configured, and it may be removed in the next minor release.                                                                                                                                                                                                                                 |

Captured context data and `MapMessage` attributes may contain sensitive information. Configure included and excluded patterns to limit the data exported as log attributes.

Declarative configuration example:

```yaml
file_format: "1.1"
instrumentation/development:
  java:
    log4j_appender:
      mdc_attributes/development:
        included:
          - request-*
          - user-?
        excluded:
          - "*-secret"
      map_message_attributes/development:
        included:
          - order-*
        excluded:
          - "*-secret"
```

The `otel.event.name` key is supported in `MapMessage` entries and context data entries. When present, its value is used as the log event name and is not emitted as an attribute.

[source code attributes]: https://github.com/open-telemetry/semantic-conventions/blob/main/docs/general/attributes.md#source-code-attributes
